# 모아오더 MVP PRD

## 서비스 개요

소상공인 공동구매 운영 + 고객 주문 참여 SaaS. 반응형 웹.
핵심 가치: **사장님과 고객 사이의 운영 혼선을 줄이는 것.**

## 사용자

| 역할 | 설명 |
|------|------|
| 사장님(owner) | 공동구매 개설, 주문 관리, 피킹/정산 |
| 고객(customer) | 매장 구독, 공동구매 참여, 주문/수령 |

하나의 서비스에서 역할만 다름. staff 역할은 구조만 준비(MVP 미사용).

## 시장 맥락

파일럿 사장님이 경쟁 서비스 + 카카오 오픈채팅을 병행 중.
경쟁 서비스의 주요 빈틈:
- 오늘 수령 상품을 바로 확인할 수 없음
- 부분취소 불가 (전체 취소 후 재주문 필요)
- 재고 처리/깜짝 할인 등 즉시성 판매를 서비스에서 처리 못함 → 카카오 병행
- 상태 알림 누락 → 사장님이 서비스를 신뢰하지 못함

## 공동구매 타입 (3가지, MVP 전부 지원)

공통 주문 흐름 위에 타입별 규칙만 분기.

| 타입 | 규칙 |
|------|------|
| 예약주문형 (기본) | 마감일 기준 집계. 가장 단순. |
| 공동구매형 | 최소 수량 미달 시 자동 취소 + 전체 환불 |
| 픽업형 | 픽업 시간대 선택 + 30분 전 리마인더 |

공구 1개 = 상품 1개 (MVP 고정).

## MVP 필수 기능

- 공구 생성/게시 (모바일 30초 등록 목표)
- 카카오 링크 공유 → 비로그인 열람 → 주문/결제
- 주문 즉시 결제 + 마감 전 부분취소/전체취소
- 자동 마감 + 수동 조기 마감
- 주문 자동 집계 + 피킹 리스트
- 오늘 수령 예정 (고객/사장님 양쪽)
- 판매 가능 수량 제한 (선택, 선착순)
- 구독 고객 자동 알림 (신규 공구)
- 상태 변화 누락 없는 알림 (인앱 + SMS/이메일 1채널)
- 마감 후 취소 요청 → 사장님 승인/거절
- 수령 완료 체크 (optional) + 공구 전체 완료

## MVP 제외

카카오 알림톡, 리뷰/문의, AI 수요예측(데이터 구조만), CSV 다운로드, 매장 탐색/검색, 임시저장, 공구 복제, 픽업 슬롯 인원 제한, 멀티매장 UI, 거래 수수료 정산, 사용자 탈퇴.

## 결제

- PG: PortOne v2 (카카오페이 + 카드)
- 주문 즉시 결제 + 마감 전 무료 취소/부분취소
- 재고 선점 → 결제 → 웹훅 검증 → 주문 확정
- 부분취소: 수량 줄이기만 (늘리기 불가, 새 주문 유도)
- 비즈니스 모델: 구독 수수료 (사장님 월정액). 거래 수수료는 MAU 확보 후 검토.

## 알림

- 인앱 필수 + SMS 또는 이메일 1채널 (MVP)
- 카카오 알림톡은 2차
- 핵심 원칙: 상태 변화가 누락 없이 전달되는 구조
- 공구 수정 알림: 마감시간/가격/픽업시간 변경만 (설명/사진 수정은 무알림)
- 픽업 리마인더: 픽업형 + 시간 지정 주문에만 30분 전

## 고객 진입

- 주 경로: 카카오 링크 공유 (사장님이 오픈채팅에 배포)
- 비로그인 상태에서 공구 상세 열람 가능
- 로그인: 카카오 소셜 단일 진입점
- 첫 주문 완료 시 자동 매장 구독 + 안내
- 딥링크 목적지 보존 (로그인 후 원래 페이지 복귀)
- 매장 탐색/검색: MVP 제외. 링크 유입 + 자동 구독으로 대체.

## 완료 기준

- 사장님이 공구를 만들고 링크를 공유할 수 있다
- 고객이 링크로 주문/결제할 수 있다
- 주문이 자동 집계되고 피킹 리스트를 확인할 수 있다
- 고객이 주문 변경/취소를 할 수 있다
- 마감 → 수령가능 → 완료 전체 흐름이 모바일 웹에서 동작한다
- 3가지 공구 타입 모두 동작한다
- 상태 변화 알림이 누락 없이 전달된다

## 제약조건

- 범용 커머스 아님. 소상공인 공동구매에 특화.
- 화면 수 최소화 (고객 9, 사장님 8, 공통 2 = 총 19개).
- 무채색 + 포인트 컬러 1개.
- 저사양 모바일 브라우저 지원 (iOS Safari 15+, Android Chrome 90+).
- 빠른 출시 > 멋진 구조. 에러 적고 디버깅 쉬운 구조 우선.
