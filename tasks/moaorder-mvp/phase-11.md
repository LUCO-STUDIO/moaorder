# Phase 11: 통합 테스트 + 마무리

## 목표
전체 핵심 흐름이 E2E로 검증되고, 빈 상태/에러 상태가 처리되며, 코드가 정리됨.

## 컨텍스트
- 설계 문서: `docs/prd.md` (완료 기준)
- 설계 문서: `docs/flow.md` (전체 사용자 흐름)
- Phase 1~10의 모든 구현물

## 구현 항목

### 1. 통합 테스트 (우선순위순)

#### 1-1. reservation 타입 E2E (1순위)
`apps/api/tests/test_e2e_reservation.py`:
```
사장님 로그인 → 매장 생성 → 공구 생성 (예약주문형)
→ 고객 로그인 → 공개 조회 (public_id) → checkout/prepare → 웹훅 mock → 주문 생성
→ 주문 상세 확인 → 수량 줄이기 → 부분환불 확인
→ 마감 (자동 or 수동) → 주문 CONFIRMED
→ 사장님 피킹 리스트 확인 → 수령 가능 변경 → 고객 알림 확인
→ 수령 체크 → 공구 전체 완료 → PICKED_UP / NOT_PICKED_UP
→ 알림 이력 확인
```

#### 1-2. group_buy 타입 E2E (2순위)
`apps/api/tests/test_e2e_group_buy.py`:
**달성 시나리오:**
```
공구 생성 (공동구매형, min_quantity=3) → 3명 주문
→ 마감 → 전원 CONFIRMED → 피킹 → 완료
```
**미달 시나리오:**
```
공구 생성 (공동구매형, min_quantity=3) → 2명 주문
→ 마감 → 전원 CANCELLED + 환불 + 알림
```

#### 1-3. pickup 타입 E2E (3순위)
`apps/api/tests/test_e2e_pickup.py`:
```
공구 생성 (픽업형 + 시간대 2개)
→ 고객 주문 (시간대 선택) → 결제
→ 마감 → 수령 가능
→ 피킹 리스트 시간대별 확인
→ 픽업 리마인더 알림 스케줄 확인
→ 완료
```

#### 1-4. 웹훅 기준
통합 테스트는 **웹훅 mock** 기준. PortOne 실 테스트 채널은 수동 테스트에서만 사용.

### 2. 에지 케이스 테스트

#### 2-1. 취소 후 재주문
```
주문 → 전체 취소 → 같은 공구에 재주문 → 성공
```

#### 2-2. 품절 처리
```
공구 (max_quantity=1) → 1명 주문 → 2번째 주문 시도 → 품절 에러
→ 1번 주문 취소 → remaining_qty 복원 → 3번째 주문 → 성공
```

#### 2-3. 마감 후 취소 요청 → 승인
```
주문 → 마감 → CONFIRMED → 취소 요청 → 사장님 승인 → 환불 → CANCELLED
```

#### 2-4. 동시성
```
공구 (remaining_qty=1) → 동시에 2건 checkout/prepare → 1건만 성공, 1건 SoldOutError
```

### 3. 프론트 빈 상태 처리
각 화면에서 데이터가 없을 때:
- 대시보드 공구 0개: "새 공구를 만들어보세요" + FAB 강조
- 고객 홈 구독 매장 0개: "매장의 공구 링크를 통해 첫 주문을 해보세요"
- 주문내역 0건: "아직 주문이 없어요"
- 알림 0건: "새로운 알림이 없어요"
- 피킹 리스트 0건: (이 경우는 발생하지 않으나 방어)

### 4. 에러 상태 처리
- 품절: 공구 상세 CTA "품절" (비활성)
- 마감: 공구 상세 CTA "마감됨" (비활성)
- 네트워크 에러: 공통 에러 토스트/메시지
- 결제 실패: "결제에 실패했어요. 다시 시도해주세요"

### 5. 프론트 E2E (후순위 — 이번 phase 범위 외)
- Playwright 기반 프론트 흐름 검증은 MVP 이후 별도 task로.
- 이번 phase의 통합 테스트는 백엔드 API 레벨 E2E 기준.

### 6. 코드 정리
- 불필요 TODO 주석 제거
- 미사용 import 제거
- console.log 제거 (프론트)
- 타입 정리 (TypeScript any 제거)
- 중복 코드 리팩토링

### 6. 최종 검증 체크리스트
`docs/prd.md` 완료 기준 대비 확인:
- [ ] 사장님이 공구를 만들고 링크를 공유할 수 있다
- [ ] 고객이 링크로 주문/결제할 수 있다
- [ ] 주문이 자동 집계되고 피킹 리스트를 확인할 수 있다
- [ ] 고객이 주문 변경/취소를 할 수 있다
- [ ] 마감 → 수령가능 → 완료 전체 흐름이 동작한다
- [ ] 3가지 공구 타입 모두 동작한다
- [ ] 상태 변화 알림이 누락 없이 전달된다
